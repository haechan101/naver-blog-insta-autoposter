# 네이버 블로그 · 인스타그램 자동 포스팅 파이프라인

공기업 채용 자료를 넣으면 블로그 글과 표 이미지를 만들고, 네이버 스마트에디터를
직접 조작해 발행까지 하는 도구입니다. 계정 8개를 번갈아 쓰면서 글마다 어투와
디자인을 바꿉니다.

같은 자료로 인스타그램 카드뉴스 8장과 캡션도 만들어, 사람이 확인한 것만
대기열에 넣고 정해진 시각에 캐러셀로 발행합니다.

Python · Anthropic API(Claude) · Playwright · PySide6 · Instagram Graph API

---

## 왜 만들었나

공기업 준비생을 대상으로 하는 교육 서비스의 유입을 블로그로 만들려고 했습니다.
기업이 69곳이고 각 기업마다 서류·필기·면접 이야기가 다르니 쓸 글이 340편쯤 됩니다.
손으로는 못 씁니다.

그런데 "자동으로 글을 뽑는다"까지는 쉽고, 실제로 부딪히는 문제는 그다음이었습니다.

1. **같은 글로 보이면 안 된다.** 계정 8개에 비슷한 글이 올라가면 네이버가
   유사문서로 처리합니다. 자동화의 성패가 여기 달려 있었습니다.
2. **네이버 에디터는 API가 없다.** 브라우저를 직접 몰아야 합니다.
3. **숫자가 틀리면 안 된다.** 배수, 과락 기준, 마감일. 교육 서비스에서
   틀린 정보는 단순 오타가 아닙니다.

아래는 그 세 가지를 어떻게 풀었는지에 대한 기록입니다.

## 전체 흐름

```
공기업 자료(md)
   │  md_loader     섹션을 쪼개고 주제 라벨을 붙임
   ▼
generator          Claude 로 본문 생성 (구조화 출력)
   │
   ├─ validator     규칙 35개로 검사 → 문제가 있으면 지적사항과 함께 재생성
   │
   ├─ image_gen     표 이미지 3종을 HTML/CSS 로 만들어 PNG 로 렌더
   ▼
publisher          Playwright 로 네이버 에디터를 채우고 발행
   │
   ▼
post_queue         무엇을 어느 계정에 썼는지 기록
```

`run_app.py`(GUI), `run_batch.py`(여러 계정 일괄), `run_daily.py`(하루 한 편),
`company_batch.py`(기업 하나를 모든 계정에)가 같은 파이프라인을 각각 다른 방식으로 부릅니다.

인스타그램은 같은 자료에서 갈라져 나갑니다.

```
공기업 자료(md)
   │  md_loader      (블로그와 같은 로더를 씀)
   ▼
insta_gen          Claude 로 카드 1~5번 문구 + 마무리 + 캡션
   │               generator 의 클라이언트·재시도를 그대로 씁니다
   ├─ 글자 검사     개수·금지어
   ▼
insta_cards        카드 8장을 1080×1350 JPEG 로 렌더 (틀 × 색)
   │
   ├─ 그림 검사     글자 넘침·줄 넘어감 → 문제가 있으면 한 번 다시 씀
   ▼
  사람 확인·수정    앱에서 문구와 스타일을 보고 고칩니다
   │
   ▼
insta_queue        [확인 완료]한 것만 대기열에. 발행 시각 자동 배정
   │
   ▼
run_insta          작업 스케줄러가 발행 시각마다 실행 → 때가 된 1건
   ▼
insta_publish      임시 공개 주소를 만들어 캐러셀 게시
```

## 유사문서를 피하려고 한 것

이게 이 프로젝트에서 가장 많이 고민한 부분입니다.

### 주제를 쪼갰다

처음에는 기업 하나에 글 하나였습니다. 그러니 69편이 끝이고, 게다가 한 편에
모든 내용을 넣으니 기업만 다르고 구성은 똑같은 글이 나왔습니다.

그래서 한 편의 단위를 **(기업 × 주제)** 로 바꿨습니다. 주제는 7종입니다.
서류·자소서, NCS 필기, 면접 실전, 기업·직무 소개, 이것만은 피하세요,
자주 묻는 질문, 전 전형 종합.

여기서 알게 된 게 있습니다. **기업마다 쓸 수 있는 주제가 다릅니다.** 자료를
재보니 NCS 이야기가 충분한 기업은 67곳 중 14곳뿐이었고, 서류는 58곳이었습니다.
자료가 없는 주제로 글을 쓰면 모델이 지어냅니다. 그래서 원문 글자 수를 주제별로
세어 `가능 / 제한적 / 자료 부족` 으로 나누고, 부족한 주제는 아예 막았습니다.

### 어투를 4종으로 나눴다

같은 사람이 쓴 티가 나면 소용이 없어서, 계정마다 어투를 다르게 했습니다.

| | 문장 맺음 | 한 줄 길이 | 정렬 |
|---|---|---|---|
| A 브리핑형 | ~습니다 / ~예요 | 18~26자 | 가운데 |
| B 대화형 | ~해요 / ~죠 / ~거든요 | 16~24자 | 가운데 |
| C 조언형 | ~것 같습니다 / ~로 판단됩니다 | 70~150자 | 양쪽 |
| D 분석형 | 수치 나열, 인사말 없음 | 20~30자 | 왼쪽 |

C가 유독 긴 이유는 네이버에서 **한 줄이 곧 한 문단**이기 때문입니다. 처음에
40~70자로 잡았더니 모델이 문장마다 줄을 바꿔서 A와 구분이 안 됐습니다(실측 30.5자).
줄글로 쓰라고 하고 기준을 70~150자로 올리니 그제야 다른 글이 됐습니다.

### 이미지도 갈랐다

어투를 나눠도 표 이미지가 똑같으면 그림만 봐도 한 곳에서 만든 티가 납니다.
그래서 스타일마다 색·모서리·글씨체를 바꿨습니다.

| | 글씨체 | 카드 바탕 | 특징 |
|---|---|---|---|
| A 브리핑형 | 맑은 고딕 | 흰색 | 왼쪽 파란 띠 |
| B 대화형 | Noto Sans KR | 연녹색 | 행이 말풍선 칩 |
| C 조언형 | 바탕(명조) | 누런 종이 | 그림자 없이 테두리만 |
| D 분석형 | 돋움 + Consolas | 다크 | 상단 주황 막대, 숫자 고정폭 |

처음엔 색만 바꿨는데 나란히 놓고 보니 A와 C가 같은 카드로 보였습니다.
색이 아니라 **모양**을 바꿔야 구분됩니다. 글씨체는 실제로 설치된 것만 골랐습니다.
CSS에 나눔고딕을 써도 없으면 조용히 맑은 고딕으로 대체되기 때문에, 렌더링 폭을
재서 진짜 다르게 나오는 폰트만 남겼습니다.

## 네이버 에디터 조작

API가 없어서 Playwright로 브라우저를 직접 몹니다. 계정마다 크롬 프로필 폴더를
따로 두고 재사용합니다. 쿠키만 저장하면 매번 새 기기로 인식돼 세션이 금방 끊깁니다.

### 알아낸 것들

문서에 없고 직접 눌러보며 알아낸 것들입니다.

- **예약 발행 날짜는 넣을 수 없습니다.** 날짜 입력칸이 readonly 이고, 달력을 열면
  모든 날짜가 비활성입니다. 네 가지 방법을 시도했지만 전부 실패했습니다. 그래서
  오늘 날짜면 바로 통과시키고, 시간대가 지났으면 예약을 포기하도록 했습니다.
- **표 버튼은 3×3 고정입니다.** 크기를 고르는 UI가 없습니다. 3×3을 넣은 뒤
  행 추가 버튼을 눌러 키웁니다. Tab으로는 행이 늘어나지 않습니다.
- **해시태그가 링크에 붙습니다.** 본문 마지막 줄이 URL이면 네이버가 링크 카드를
  만드는데, 그게 끝나기 전에 태그를 치면 URL 뒤에 그대로 붙습니다. Enter를 먼저
  누르고 DOM이 조용해질 때까지 기다린 뒤에 태그를 칩니다.

### 본문 문법

글은 자체 표기법으로 만들고 발행할 때 에디터 조작으로 바꿉니다.

```
[[H]] 소제목          [[HR]] 구분선        [[IMG:파일명]]
[[TABLE]] a||b // c||d                    [[ALIGN:center]]
**굵게**  <blue>파랑</blue>  <hl>형광</hl>  [글자](주소)
```

앱에서 초안을 고칠 수 있게 CKEditor를 붙였는데, 이 표기법과 HTML을 서로
변환해야 했습니다(`dsl_html.py`). CKEditor 5는 못 썼습니다. 기본 빌드에
글자색·구분선·임의 HTML 기능이 없고, 전체 빌드는 협업 기능 의존성 때문에
초기화가 안 됐습니다. 4로 내려서 해결했습니다.

## 검증

`validator.py` 에 규칙 35개가 있습니다. 분량, 줄 길이, 소제목 개수, 이미지 장수,
금지 표현, 제목 연도, 반말체, 빈 줄 비율 등입니다. 걸리면 지적사항을 모델에게
돌려주고 다시 씁니다(최대 3회).

규칙이 스타일과 주제를 따라갑니다. 예를 들어 빈 줄 상한은 보통 75%인데
조언형만 120%입니다. 조언형은 문단마다 빈 줄을 넣는 게 정상이라, 75%로 고정했더니
규칙과 작성 지침이 서로 반대를 요구해 재생성만 세 번 돌았습니다.

**한계도 분명합니다.** 35개가 전부 세는 규칙입니다. 글자 수, 개수, 정규식.
그래서 "숫자가 원문과 맞는가"는 못 잡습니다. 이 글들은 배수와 마감일이 핵심인데
그걸 검증하는 장치가 아직 없습니다. 다음에 만들 것 1순위입니다.

## 인스타그램 카드뉴스

블로그와 같은 자료를 쓰지만 부딪힌 문제가 달랐습니다.

### 인스타 API 는 사진 파일을 안 받는다

이미지 게시에 로컬 파일 업로드가 없습니다. 인스타 서버가 **공개 주소에서 JPEG 를
직접 가져갑니다**(로컬 업로드는 동영상만). 카드뉴스를 올리려면 그림이 인터넷에서
보여야 하는데, 이 도구는 개인 PC 에서 돌고 서버가 없습니다.

발행하는 1~2분 동안만 주소를 만들어 쓰고 닫습니다.

1. 카드 폴더의 `card*.jpg` 만 내보내는 작은 웹서버를 `127.0.0.1` 에 띄웁니다
2. cloudflared 임시 터널로 `https://<무작위>.trycloudflare.com` 주소를 받습니다
3. 그 주소로 캐러셀을 만들어 게시합니다
4. 터널과 웹서버를 닫습니다

터널이 PC 에서 바깥으로 나가는 연결이라 공유기 포트포워딩이나 방화벽 설정이
필요 없습니다. 내보내는 것도 그 기업 카드 폴더의 JPEG 뿐입니다.

### 서비스 설명은 모델에게 맡기지 않았다

8장 중 **6·7번(기능 소개)과 8번(제목·저장 문구)은 고정 문구**입니다.
서비스 설명을 매번 새로 쓰게 하면 없는 기능을 약속하는 문장이 섞입니다.
모델이 쓰는 건 자료에서 나오는 1~5번과 캡션까지입니다.

카드뉴스는 피드에 오래 남으므로 블로그와 달리 **채용 일정·인원을 쓰지 않고**
시험 구성만 씁니다. 지난 채용 기준 숫자가 몇 달 뒤에도 그대로 보이면 틀린 정보가 됩니다.

### 피드가 똑같아 보이지 않게 — 틀 × 색

블로그에서 유사문서를 피한 것과 같은 고민입니다.

| | |
|---|---|
| 틀 | `white` 화이트 볼드 · `navy` 네이비 금융 · `note` 노트 필기 (배경·글꼴·장식) |
| 색 | `base` 틀의 기본 강조색 · `brand` 기업색 |

기업색은 기업 로고에서 뽑고, 배경 위에서 읽히도록 밝기를 자동으로 맞춥니다.
노란 KB 로고색은 흰 바탕에서 진한 금색이 되고, 강조 밑줄만 원래 노란색으로 남습니다.

문구는 `deck.json` 으로 함께 저장하므로, 문구를 그대로 두고 스타일만 바꿔
다시 렌더할 수 있습니다.

### 사람이 확인한 것만 올라간다

글이 아니라 그림이라 자동 검증의 한계가 더 큽니다. 글자 넘침과 줄 넘어감은
렌더한 그림에서 잡아내지만, 디자인이 어색한 건 못 잡습니다. 그래서 **반자동**입니다.

- `[확인 완료]` 를 누른 카드만 대기열에 들어갑니다
- 확인한 뒤 문구·캡션·스타일·카드 그림이 바뀌면 지문을 비교해 `다시 확인 필요` 로 멈춥니다
- 한 번 실행에 1건만. 실패하면 다음 시각으로 미루고 3번 실패하면 멈춥니다
- 이미 올린 기업은 다시 올리지 않습니다

발행은 윈도우 작업 스케줄러가 `run_insta.py` 를 정해진 시각에 부르는 방식이라,
PC 가 꺼져 있던 시각의 카드는 다음 시각에 올라갑니다.

### 인스타 제한

캐러셀 2~10장 · JPEG 만 · 장당 8MB 이하 · 캡션 2,200자 · 해시태그 30개 · 24시간 100건.
어기면 API 가 거절하므로 만들 때 미리 맞춥니다. 카드는 1080×1350(4:5)으로,
정사각형보다 피드에서 화면을 더 차지합니다.

- `.env` 의 `INSTAGRAM_ACCESS_TOKEN` — Instagram API with Instagram Login 토큰
- `tools/cloudflared.exe` — [cloudflare/cloudflared](https://github.com/cloudflare/cloudflared)
  공식 배포 파일을 직접 받아 넣습니다 (저장소에 넣지 않았습니다)

```bash
venv\Scripts\python.exe insta_publish.py --test 기업명    # 임시 주소만 시험 (인스타에 안 보냄)
venv\Scripts\python.exe run_insta.py --list             # 대기열 보기
venv\Scripts\python.exe run_insta.py --dry              # 지금 돌면 무엇을 올릴지만
```

### 필요한 폴더 구조

기업 자료는 `../공기업 분석/{기업명}.md` 에서 읽습니다. 파일은
`# 1. 제목` 형태의 대제목으로 나뉘어 있어야 하고, `md_loader.py` 가 그 제목을
보고 주제를 분류합니다.

인스타 사진과 산출물은 저장소 바깥의 형제 폴더를 씁니다.

```
Naver_blog/
├─ auto_poster/                     ← 이 저장소
├─ 공기업 분석/{기업명}.md            ← 자료 (직접 넣습니다)
└─ auto_insta/
   ├─ insta_images/{기업명}/로고.png  ← 표지 로고 (기업색도 여기서 뽑습니다)
   ├─ insta_images/{기업명}/건물.jpg  ← 표지 배경. 없으면 남색 배경
   ├─ insta_images/_톰슨에듀AI/       ← 브랜드 로고·기능 캡처
   └─ insta_out/{기업명}/card01.jpg  ← 만든 카드 (자동 생성)
```

사진이 없어도 돌아갑니다. 로고가 없으면 글자로, 건물 사진이 없으면 단색 배경으로
대체하고, 폴더는 첫 실행 때 자동으로 만듭니다.

---

## 이 저장소에 없는 것

코드만 올렸습니다. 아래는 제외했습니다.

- **기업 분석 자료** — 직접 정리한 자료라 공개하지 않습니다
- **네이버 로그인 세션** (`browser_profile/`) — 있으면 로그인 없이 글을 쓸 수 있습니다
- **블로그 아이디** — `accounts.py` 대신 `accounts.example.py` 를 뒀습니다
- **생성된 글과 이미지** (`drafts/`, `images/`)
- **API 키와 인스타 토큰** — `.env` 로 뺐습니다
- **인스타 사진과 카드** (`../auto_insta/`) — 기업 로고·건물 사진은 직접 모은
  자료이고, 만든 카드는 산출물입니다
- **cloudflared 실행 파일** (`tools/`) — 공식 배포처에서 직접 받아 넣습니다

자료 없이도 파이프라인 구조와 에디터 조작, 카드 렌더 부분은 그대로 읽힙니다.

## 파일

| | |
|---|---|
| `md_loader.py` | 자료를 읽고 섹션을 주제별로 분류 |
| `topics.py` | 주제 7종 정의와 자료 충분도 판정 |
| `personas.py` | 어투 4종. 검증 기준을 함께 들고 있음 |
| `generator.py` | Claude 호출. 구조화 출력으로 제목·본문·태그·표를 한 번에 |
| `validator.py` | 규칙 35개 |
| `image_gen.py` | 표 이미지. 스타일별 테마 |
| `html_render.py` | HTML/CSS 를 PNG 로 (Playwright 스크린샷) |
| `publisher.py` | 네이버 에디터 조작과 발행 |
| `dsl_html.py` | 자체 표기법 ↔ HTML 왕복 변환 |
| `post_queue.py` | 무엇을 어느 계정에 썼는지 |
| `company_batch.py` | 기업 하나를 모든 계정에 한 편씩. 주제 배정과 발행 시각 분산 |
| `run_app.py` | PySide6 GUI. 블로그와 인스타 탭 |
